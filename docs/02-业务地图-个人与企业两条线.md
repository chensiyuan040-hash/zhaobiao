# 02 · 业务地图：个人与企业两条线

> 把“个人 / 企业”翻译成更准的一句话：  
> **个人买的是“多赚钱、少操心”，企业买的是“少担责、能交差”。**

---

## 0. 分法修正

按客户大小分不够准。真正决定产品形态的是两件事：

1. **谁掏钱**：老板本人，还是组织 / 部门预算。
2. **为什么掏钱**：多来客、少丢客、省时间；还是少担责、能交差、有亮点。

---

## 1. 个人侧：六层需求地图

| 层面 | 商店 | 茶叶店 | 美容院 |
|---|---|---|---|
| **内容获客**（朋友圈 / 短视频 / 活动） | 中 | 强 | 强 |
| **客户资产**（偏好 / 生日 / 卡到期 / 回访） | 弱-中 | 强 | 强 |
| **商品库存**（临期 / 周转 / 选品） | 强 | 强 | 中 |
| **员工管理**（排班 / 提成 / 流失 / SOP） | 弱 | 弱-中 | 强 |
| **数据统计**（流水 / 毛利 / 动销 / 复购） | 强 | 强 | 强 |
| **库存 / 合规风险**（食品 / 广告 / 预付卡） | 中 | 中 | 强 |

> 说明：强弱是“痛点强度 + 付费意愿”的综合判断，不是绝对结论，需线下访谈校正。

---

## 2. 员工管理：只对美容院是刚需

- **美容院**：排班、预约、提成核算、技师流失带走客户、服务标准不统一——真刚需。
- **商店 / 茶叶店**：多是夫妻店或一两个店员，老板真正怕的是“人不靠谱、盘点对不上”，不是缺一套排班软件。
- **结论**：员工管理可以做成美容院的模块，但**不要当成三类店的共性**。

---

## 3. 数据统计：共性最强，但录入是死穴

- 三类店都痛，但痛的不是“没有报表”，是**数据根本不全**。
- 死穴是录入：老板不愿每天记账，店员嫌麻烦；系统没数据 → 报表没用 → 老板更不用。
- 所以不要做又一个 dashboard。更现实的产品形态：

> **从现有收银 / 进销存 / 微信导出 → AI 清洗 → 每天一句话 + 三条行动建议**  
> 再用语音、拍照记账补缺口。

### 三类店的数据重点

| 店铺 | 关键数据 |
|---|---|
| 商店 | 流水、毛利、品类动销、临期库存、烟档位 |
| 茶叶店 | 库存周转、客户偏好、送礼节点、应收 / 赊账 |
| 美容院 | 耗卡、到店频次、沉睡会员、员工业绩 |

---

## 4. 你漏掉的三层，而且是最值钱的

### 4.1 内容获客

- 老板已经在用豆包写，但写一条停一条。
- 这是 `video-studio` 最能直接接上的一层：一句话 → 15–30 秒能发的视频。
- 价值：直接对应“来客”，老板最容易感知。

### 4.2 客户资产

- 谁买过什么、偏好、生日、卡到期、该回访了。
- 它在“员工管理”和“数据统计”中间，是复购的命门，也是员工离职带不走的东西。
- 茶叶店、美容院最强；商店可以做熟客 / 社区群。

### 4.3 库存 / 合规

- 商店：临期、烟档位、食品保质期。
- 茶叶店：茶类周转、批次、年份。
- 美容院：预付卡、广告合规（不能宣称疗效）。
- 特点：不出事没感觉，一出事就是大事。适合“提醒 + 检查清单”，不适合重系统。

---

## 5. 核心矛盾

> 小老板**最愿意掏钱**的是“来客 / 留客”（收入端）；  
> **最容易做成产品**的是“数据 / 员工管理”（内部端）。  
> 这两件事不重合。

- 先做员工管理 / 数据统计：产品好做，但商店和茶店老板未必买。
- 先做内容获客：老板买，但交付重、难复制、靠人。

**建议：用内容获客做入口，用客户资产 / 数据统计做留存和加购。**

---

## 6. 企业侧：查资料、做报表，各对一半

### 6.1 查资料——对

“查”只是动作，他要的是“写材料时找得到依据、引用不出错”。  
这正是 `okf_kb` 的强项：出处、版本、权限、审计。

### 6.2 做报表——只对一半

报表的核心是数据口径和取数权限，`okf_kb` 不是 BI。  
真接这个，需要 Excel / Python / BI 能力；国企数据多在财务 / 业务系统里，取数审批是门槛。  
更稳的是做“报表说明 / 经营分析报告”，不碰底层数字。

### 6.3 完整场景表

| 场景 | 频率 | 痛点 | okf_kb 适配度 |
|---|---|---|---|
| 写汇报 / 总结 / 讲话稿 | 高 | 拼材料慢、怕不到位 | 中（素材库 + 初稿） |
| 查政策 / 制度 / 同业案例 | 高 | 散、找不到、怕引错 | 高 |
| 会议纪要 / 待办跟踪 | 高 | 人工整理、跟进漏 | 中（需语音转写） |
| 做报表 / 经营分析 | 高 | 数据散、口径不一 | 低 |
| 制度梳理 / 权责清单 | 中 | 集团化窗口期、部门墙 | 高 |
| 尽调 / 可研资料整理 | 中 | 文档多、版本乱 | 高 |
| 合规检查 / 审计留痕 | 中 | 要出处、要权限 | 高 |

## 7. 金桂的时效性机会

按公开信息，泸州金桂控股是市属国企金融控股集团，2026 年 8 月刚完成集团化更名。最有时效性的切入是：

1. **制度 / 流程 / 权责梳理**——集团化窗口期，内部正在做整合；交付物是一份能上会的材料。
2. **监管政策跟踪简报**——金融国企长期刚需；可以做成定期简报，`okf_kb` 做后台。
3. **材料初稿**——小领导个人最痛；30 分钟出三级大纲 + 初稿 + 引用清单。
4. **尽调 / 可研资料库**——文档密集，知识图谱适配度高。

### 不要一上来卖平台

- 小领导通常不是掏钱的人；他能提需求、找场景、当内部推手。
- 预算要走部门 / 信息中心 / 采购；国企可能要求资质、比价、招标。
- 第一单最好是“部门级轻咨询 / 小试点”，或挂靠已有供应商。

---

## 8. 现实约束

| 约束 | 影响 |
|---|---|
| 小领导没有预算权 | 需要他向上引荐，或先做免费 / 低价试点 |
| 国企采购流程 | 周期长，可能需要资质、比价、招标 |
| 数据安全责任 | 一旦出问题，个人担不起；必须内网、权限、审计 |
| 效果难量化 | 知识库的价值不如“多来一个客”直观，需要材料 / 时间节省来证明 |
| 交付能力 | 一个人做，服务客户数量有上限；要尽早产品化 / 模板化 |

---

## 9. 建议

**两边都先卖“一份看得见的结果”，再谈系统。**

### 个人侧

- 先做“客户资产 + 内容”的月度服务。
- 数据统计作为第二个月加购。
- 员工管理只对美容院做模块。

### 企业侧

- 先卖“一次制度 / 政策梳理 + 一份材料”。
- `okf_kb` 放后台；用一个小场景证明“内网可用、有出处、可审计”。
- 再谈部门级试点。

### 共同原则

> 先交付一份看得见的结果，再谈系统。  
> 先让客户说“这个有用”，再让客户说“多少钱”。

## 10. 开放问题

- [ ] 个人侧先做哪一类店？三类店需求差异大，同时做容易失焦。
- [ ] 做“替老板干”的服务，还是“给老板用”的工具？
- [ ] 定价：月度服务几百还是几千？企业试点几万？
- [ ] 金桂这条线，是当现金流还是当案例？回款周期能否接受？
- [ ] 一个人交付的上限是多少？哪些环节必须模板化 / 自动化？
